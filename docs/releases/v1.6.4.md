# ScreenScoreBoard v1.6.4

> **把“存储”和“口味”都交给你。**
> 9 种存储后端可在管理端直接切换，管理端 6 套主题随时换装。

## ✨ 本版亮点

### 🗄️ 9 种存储后端，管理端直接切换

| 类别 | 后端 |
|---|---|
| 文件 | JSON、TXT（人类可读缩进 JSON）、SQLite |
| 数据库 | PostgreSQL、MySQL / MariaDB、MongoDB、SQL Server、Oracle（Thin）、Redis |

打开管理端「存储后端」即可：

1. 选择后端并填写连接参数；
2. **测试连接**，确认延迟与目标是否已有数据；
3. 选择 **迁移现有数据** 或 **新后端从空库开始**；
4. 保存后重启服务生效。

存储配置独立保存在 `DATA_DIR/storage.json`（权限 `0600`），优先级高于存储相关环境变量。数据库密码**不会**进入项目状态、WebSocket 广播、导出或备份，也不会通过 API 回传前端。

### 🛡️ 更可靠的持久化

- **revision 乐观并发（CAS）**：SQL/MongoDB/Redis 使用整数版本号，JSON/TXT 使用内容哈希；检测到外部写入时停止落盘并降级健康状态，避免旧快照覆盖新数据。
- **跨主机单写者保护**：PostgreSQL advisory lock、MySQL `GET_LOCK`、Redis `SET NX PX` + 续租。
- **连接超时与重试**、`/api/v1/storage/health` 健康诊断（revision、延迟、锁状态、警告）。
- **旧表自动升级**：旧 SQLite / PostgreSQL / MySQL 表启动时自动补 `revision` 列，无需手工迁移。

> Redis 作为权威存储时请开启 `appendonly yes`，并设置 `maxmemory-policy noeviction`。无法保证持久化时建议选择 PostgreSQL。

## ⚠️ 升级须知

- **Node.js 24 起**（延续 1.6.3）。升级后请执行 `npm install`，并用 Node 24 重建原生模块：`npm rebuild better-sqlite3`。
- 新增的可选数据库驱动（`mongodb` / `mssql` / `oracledb` / `redis`）按需加载；未安装时只影响对应后端。
- 在管理端保存或迁移存储配置后**需要重启服务**；迁移前请备份整个 `DATA_DIR`。
- 迁移写入的是保存时刻的快照；到重启前对旧后端的写入不会同步到新后端。
- 管理端旧主题值 `dark` / `light` 会自动兼容，无需清理 localStorage。
- `data/` 旧 JSON 数据与 WebSocket 协议保持兼容；已有环境变量配置仍可用。
