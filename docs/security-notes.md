# 安全说明

> **一句话：本版本已内置账号、角色、会话与 API 令牌鉴权；显示端仍是公开只读。远程部署请使用 HTTPS，并明确应用内不做任何 WS/HTTP 限流。**

## 现状

| 能力 | 当前状态 |
|---|---|
| 登录 / 会话 | 账号密码 + HttpOnly 会话 Cookie + CSRF 双提交 |
| 角色与权限 | `admin` / `operator` / `viewer` / 匿名；服务端 `applyOp` 与路由统一校验 |
| 开放模式 | 管理员可在「访问控制」关闭登录系统；所有访问者按管理员处理，设置持久化到 `auth.json` |
| API 令牌 | 支持，`Authorization: Bearer`，只存 SHA-256，可吊销 |
| 限流 / 防暴力破解 | **明确不做**（无失败计数、锁定、退避、验证码、429） |
| 审计日志持久化 | 无；仅记录登录成功/失败、权限拒绝、用户/会话/令牌变更 |
| HTTPS | 支持反代终止 TLS，也支持 Node 内置 HTTPS（证书路径环境变量） |
| WebSocket `/ws` | 握手校验 Cookie/Bearer；匿名只读；按 op 鉴权；吊销即关闭 |
| REST `/api/v1` | 按 route 校验角色；Cookie 写请求校验 CSRF |
| HTTP MCP `/mcp` | 仅管理员（Cookie 或 Bearer）；进程内调用继承同一 actor |
| stdio MCP | 通过 `SCOREBOARD_TOKEN` 携带 Bearer；无令牌只能读公开接口 |
| Electron | 本地模式默认仅 loopback 且关闭鉴权；勾选「启用登录（局域网共享）」后监听 `0.0.0.0` 并启用鉴权；远程管理模式由远程服务鉴权；远程屏幕模式只加载公开显示端网址 |

完整配置与部署示例见 [authentication.md](authentication.md)。

## 已有防护

- 密码使用 Node 内置 scrypt，未知用户也执行假哈希，降低响应时间枚举。
- 会话 Cookie `HttpOnly; SameSite=Lax; Path=/`；HTTPS 下 `Secure`。
- Cookie 认证的写操作要求 `X-CSRF-Token`；Bearer 豁免。
- 所有非 GET 请求校验 Origin/Referer；跨站 WebSocket 直接拒绝。
- 旧版 `/api/*` 由集中守卫覆盖，未知路径默认 admin（fail closed）。
- `/api/v1/ops` 与 `/projects/:id/ops` 在 `applyOp` 层按 op 复核，无法借逃生通道提权。
- 上传按文件头嗅探并限制类型/大小；静态资源路径做规范化，避免目录穿越。
- 主题脚本在沙箱中执行（受限 API、超时/指令上限），不是任意 Node 代码。
- HTTPS 下可加 HSTS；基础安全响应头保持。
- 单实例锁避免同一 `DATA_DIR` 被两个进程同时写入。

## 威胁模型与已知边界

适用于：学校/家庭/办公室、单机 Electron、有 HTTPS 的小型远程部署。

仍需注意：

- **显示端公开**：匿名 WS 会收到全部项目的快照；不要把显示链接发给不可信的人，除非你接受项目名/人员/分数公开。
- **不做限流**：公网暴露时暴力破解可持续尝试；请使用强密码、HTTPS、防火墙/反代访问控制等网络层手段，应用内不会返回 429。
- **多实例**：`auth.json` / `sessions.json` 是本地文件；Postgres/MySQL 共享 state 时用户与会话不跨实例共享。本期按单实例设计。
- **存储凭据**：管理端保存的数据库密码写在 `DATA_DIR/storage.json`，权限 `0600`；仅管理员 API 可读写，密码不回传前端，也不进入项目状态/广播/导出/备份。但 root、容器管理员或能读取 `/data` 的备份仍可看到明文，请限制目录权限并避免把该文件提交到版本库。
- **开放模式与存储配置**：开放模式下所有访问者都是管理员，可修改存储后端。修改前请先启用登录系统。
- **无完整审计**：没有逐 op 操作人追踪；需要合规审计时请自行接入日志系统。
- **Electron 本地模式**：默认关闭鉴权且只绑定 `127.0.0.1`；勾选「启用登录（局域网共享）」后会监听 `0.0.0.0` 并启用账号鉴权，请只在可信局域网使用。无论是否启用鉴权，同一台机器上的其他本地进程仍可访问，请把它当作本机工具。
- **开放模式（部署模式）**：管理员关闭登录系统后，任何能访问服务端口的人都拥有管理员权限，可修改分数、设置、用户与令牌，也可重新启用登录。仅建议在可信局域网 / VPN / 带访问控制的反代后使用；公网部署请保持登录系统开启。
- **自签证书**：Electron 远程管理模式不忽略证书错误；需要先在系统信任链中安装。远程屏幕模式允许任意 http/https 网址，请只填入可信页面。

## 部署建议

1. 首次启动设置 `ADMIN_PASSWORD`，或只在本机完成网页初始化。
2. 远程部署置于 Caddy/Nginx HTTPS 反代之后，Node 设置 `HOST=127.0.0.1`、`TRUST_PROXY=1`。
3. 反代保留原始 `Host`，并转发 `Upgrade` / `Connection`。
4. 定期备份 `DATA_DIR/auth.json`、`DATA_DIR/storage.json`；`sessions.json` 可选。切换存储后端前先备份整个 `DATA_DIR`。
5. 用管理员/操作员账号区分权限，手机记分员只发 operator 账号。
6. 自动化客户端使用 API 令牌，不把管理员密码写进脚本。
7. 不要把 `DATA_DIR` 放在共享目录；单实例锁依赖本地文件系统语义。
8. 活动结束后在「账号与安全 → 访问控制」重新启用登录系统，并检查管理员账号。
