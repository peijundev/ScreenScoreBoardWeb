# 安全说明（当前版本）

> **一句话：当前版本没有鉴权，只适合可信局域网或本机。** 这是有意为之的阶段性取舍，不是遗漏。

## 现状

| 能力 | 当前状态 |
|---|---|
| 登录 / Token / Session | 无 |
| 角色与权限 | 无；所有客户端拥有同等读写权限 |
| 限流 / 防暴力破解 | 无 |
| 审计日志持久化 | 无（写操作有运行日志，但不构成审计） |
| HTTPS | 由部署层决定，服务本身不终止 TLS |
| WebSocket `/ws` | 无鉴权，仅校验 Origin |
| REST `/api/v1` | 无鉴权，仅校验 Origin；`server/api/index.js` 的 `authorize()` 是预留钩子，当前恒为 `true` |
| HTTP MCP `/mcp` | 无鉴权，等价于开放全部写权限；仅复用 Origin 校验 |
| stdio MCP | 无鉴权，通过 `SCOREBOARD_URL` 连接本机或内网服务 |

## 已有的基础防护

- 管理端/显示端与 REST 响应带 `X-Content-Type-Options: nosniff` 等基础安全头
- WebSocket、REST `/api/v1` 与 HTTP MCP 都校验 `Origin`：无 `Origin` 的原生客户端放行；带 `Origin` 时必须与 `Host` 同源，或命中 `ALLOWED_ORIGINS`
- 上传按文件头嗅探并限制类型/大小；静态资源路径做规范化，避免目录穿越
- 主题脚本在沙箱中执行（受限 API、超时/指令上限），不是任意 Node 代码
- Electron 模式以 `host: '127.0.0.1'`、随机端口启动，仅本机可访问
- 单实例锁避免同一 `DATA_DIR` 被两个进程同时写入

Origin 校验只防浏览器跨站请求，**不防**任何能直接发 HTTP 请求的程序；不要把它当鉴权。

## 威胁模型

适用于：

- 学校/家庭/办公室可信局域网；
- 本机 Electron；
- 临时演示环境。

不适用于：

- 公网暴露（端口映射、云主机直接开放 `3000`）；
- 不可信访客网络；
- 多租户或需要区分管理员/观众的部署。

在不可信网络中，任何能访问端口的人都可以改分、删项目、覆盖主题、上传文件、读取全部状态。HTTP MCP 让这件事对 AI 客户端同样成立。

## 部署建议

1. **默认只监听内网**：确认防火墙未把 `3000` 暴露到公网。
2. **Electron 优先**：单机使用直接用 Electron，服务只绑 `127.0.0.1`。
3. **需要远程时用隧道/反代加一层**：至少加 HTTPS、访问控制和来源限制，但请注意这仍不能替代应用内鉴权。
4. **定期备份**：`GET /api/v1/backups`、`POST /api/v1/backups/run`，或直接备份 `data/`。
5. **不要把 `DATA_DIR` 放在共享目录**：单实例锁依赖本地文件系统语义。

## 远程化时必须补齐（后续版本）

1. **鉴权**：Token 或账号体系；`authorize(req)` 已在 REST 入口预留，MCP HTTP 与 WebSocket 也需要接入同一套主体识别。
2. **授权**：区分只读观众、记分员、管理员；MCP 工具按权限过滤，破坏性工具单独授权。
3. **限流与配额**：登录、写操作、上传、MCP 调用分别限流。
4. **审计**：记录谁在何时改了什么（至少主体、动作、资源、结果；敏感参数脱敏）。
5. **CSP 与 CSRF**：浏览器端加严格 CSP；带 Cookie 的写接口加 CSRF 防护。
6. **传输安全**：TLS 终止、HSTS、安全 Cookie。
7. **密钥与配置**：Token 轮换、最小权限、启动时拒绝默认弱口令。
8. **MCP 边界**：默认只读或按项目授权；危险工具需显式确认；限制请求体与并发。

在这些完成前，请把本项目当作「可信网络内的工具」，而不是「可公开部署的服务」。
